# Sega SG-1000 consoles

The runtime has three stable profiles: `sega-sg-1000-ntsc`,
`sega-sg-1000-pal` and `sega-sg-1000-ii-ntsc`. Each now has a fixed
machine owner over `common-sega-sg-1000`, with one shared family runtime. The II profile describes the early TMS9918 configuration;
it does not qualify later TMS9118 or custom-VDP board populations. Original
board photographs show that those populations cannot be reduced to a case
change. Further board populations remain [#2144](https://github.com/emu198x/emu198x/issues/2144).

## Implemented surfaces

The family binary is `emu198x-sega-sg-1000`. Native UI is its default build
feature; `--no-default-features` builds the headless script/MCP path. The
public `--help` lists cartridge, model/region, frame, screenshot and audio
capture options. A cartridge is required; the console has no boot firmware.
All three model IDs are accepted by the existing model parser.

```sh
cargo run -p emu198x-sega-sg-1000 -- --cart game.sg --model sega-sg-1000-ntsc
```

The current wiring provides 1 KiB console RAM, a flat cartridge window up to
48 KiB, TMS9918-family video, SN76489 audio and two controllers. Sega's product
page lists the console hold button; the existing host pause input drives NMI.
This does not implement an SC-3000 keyboard or PPI. The SC-3000 needs its own
machine implementation ([#224](https://github.com/emu198x/emu198x/issues/224),
[#225](https://github.com/emu198x/emu198x/issues/225)); cartridge mapping remains
[#223](https://github.com/emu198x/emu198x/issues/223).

## Saves and current evidence

The runtime writes complete v6 states. V5 NTSC and early-II states retain
exact readers; v5 PAL states reject explicitly before decoding because their
clock/phase model cannot provide exact continuation. Three immutable original captures
retain cartridge, RAM, held controls/NMI and partial-field state, then compare
the first three resumed fields of video, audio sample bits, clock deltas and
final state. A deliberately corrupted output fails before the restored
original passes. The cartridge and all emitted evidence are project-written.
The NTSC/early-II checks preserve original v5 behaviour. The original PAL
state is retained as a rejection fixture; corrected PAL v6 states separately
compare the first three continued fields and complete final state. Seven direct
tests per owner exercise guest execution, RAM mirroring, native boundaries,
video/audio controls, held input/NMI/restore and foreign-video-board rejection.
These checks do not establish historical software or every physical board's accuracy. The external cartridge-boot test
remains ignored without its required media.

NTSC retains its existing 3:2 VDP-dot/CPU-T-state phase. PAL now accumulates
its independent 10,738,635 Hz VDP oscillator against a nominal 3,580,000 Hz
CPU/PSG clock, with the VDP dividing its oscillator by two for dots. The profile,
PSG resampler, native-host pacing and display metadata agree with that model.
The former audio/time mismatch is tracked in
[#2223](https://github.com/emu198x/emu198x/issues/2223). Raster phase is checked at
several elapsed clock counts and audio/time agreement across three successive
windows. The nominal circuit model is corroborated by manufacturer SC-3000
clock evidence and a console report; it does not qualify every PAL revision or
claim a new physical waveform measurement.

The three public pages have separate 120-native-field captures of the existing
project-written white-backdrop cartridge. An inactive control stays black.
These are CPU/port/VDP-register smoke checks, not historical-software images or
full graphics/audio qualification. The pinned browser family still carries the
old PAL clock contract and can switch variants, so all SG embeds are omitted
until a corrected family module is published. The former family URL redirects
to the NTSC page.

The current slice verifies synthetic execution and the headless launch help.
Native menu interaction, host audio-device output and newly repeated original
cartridge qualification are not established by those observations. See
[source PR #2222](https://github.com/emu198x/emu198x/pull/2222), the
[primary-source audit](https://github.com/stevehill1981/198x/pull/291) and the
[plan](../../plans/2026-11-01-sg1000-and-board-identity-audit.md).
