# Atari 5200 SuperSystem

## Status: Boots Pac-Man to its menu

Headless extended system. The ATARI logo → cart handoff → Pac-Man title/menu
renders in correct colours. 6502 "Sally" + ANTIC + GTIA + POKEY — the same chip
family the 800XL/130XE share, so this extraction is the 8-bit Atari foundation.

## What works

- **6502 "Sally" + ANTIC (display list/DMA) + GTIA (video, P/M, collision) +
  POKEY (4-ch audio, pot scanner).**
- **Boot to the Pac-Man menu** (2026-06-04) — logo, `JMP ($BFFE)` handoff, title
  text in the right colours. Smoke `tests/cart_boot.rs` asserts a real frame
  (≥4 colours, ≥1000 non-bg px) when a BIOS is present.
- **Cart mapping** — size-mirrored 4K/8K/16K/32K; 16K uses the two-chip (EE_16)
  decode (see disproven).
- **Four controllers** — independent analogue axes on POT0–7 and lower fire
  on GTIA TRIG0–3. Runtime ports 1–4 select physical controllers; port 0 aliases
  the first, and unsupported ports are ignored.
- **Keypads and upper fire** — GTIA CONSOL selects held keypad switches on
  POKEY KR1 and upper fire (`fire2`) on KR2. The physical scanner retains its
  /114 phase, debounce, sampled Control/Shift and Break transitions. Multiple
  held switches preserve the controller's diode-free ghost connections.
- **Snapshots** — writer 20 preserves the physical scanner and all four held
  input caches. Earlier envelopes are rejected before decoding. Restored
  cartridge/BIOS bytes and explicit cartridge layouts survive reset and
  firmware replacement.

## Board identity

Atari's *CX5200 Field Service Manual*, Rev. 4 (July 1983), pp. 1-1–1-2,
distinguishes CA018087 (original four-port), CA020108 (four-port universal)
and CA021374 (two-port universal). The universal boards change buffer/decode
parts; the two-port board also removes ports 3/4 and two ICs. These three
manufactured boards still need separate fixed owners under #2144. The
corrected four-controller path is not qualification of all three boards.

The runtime exposes NTSC only. Experimental PAL timing in the Rust engine
is not evidence of a manufactured PAL 5200. Analogue charging calibration
and CX53 Trakball behaviour remain outside the controller correction.

Controller evidence: [scanner correction](https://github.com/emu198x/emu198x/pull/2239),
[restored-media correction](https://github.com/emu198x/emu198x/pull/2241), and
[executed probes](../../plans/2026-11-02-atari5200-controller-evidence/README.md).

## Not implemented / accuracy gaps

- **Exact per-character DMA positions** — DMA is now spread across the fetch
  window `[cycle 32, 104)` and WSYNC releases at HSYNC (phase 4), but the steal
  is an even split, not the exact mode-dependent per-character fetch slots.
- **Audio** — POKEY buffer drained but no WAV.
- **No native window.**

## Known unknowns / disproven hypotheses

- **DISPROVEN: "16K carts map linearly to `$8000-$BFFF`."** Real 16K 5200 carts
  are two 8K chips selected by CPU A15; the linear map put Pac-Man's entry vector
  in padding → executed garbage → NMI storm. Fixed (`sixteen_kb_two_chip_decode`).
- **DISPROVEN: "ANTIC reads only RAM."** It was handed a 16K RAM view, so a
  display list in cart ROM / glyphs in BIOS were unreachable (uniform black).
  Now a 64K `dma_mem` image. 
- **DISPROVEN: "text modes all use the mode-2 convention."** Modes 6/7's colour
  bits leaked into the glyph index ("PLAYER"→"player"); each text family now
  decodes per hardware (guarded by unit tests).
- **Verification targets** — WSYNC/DMA interleave + full GTIA P/M timing against
  the Atari hardware manual / Altirra.

## Validated against

- Pac-Man (1982, 16K NTSC) + 5200 BIOS → menu; `tests/cart_boot.rs`.
- ANTIC/GTIA chip tests (14/14, 9/9); text-mode unit tests.

## Timing & cycle-accuracy

- **Master clock & dividers** — colour clock is the master; CPU + POKEY tick every
  **2nd** colour clock ≈ 1.79 MHz NTSC. ANTIC processes one scan line per 228-clock
  boundary.
- **Timing model realised** — **per-colour-clock GTIA** (2026-06-08): the machine
  hands ANTIC each line at its left edge and composites the playfield
  left-to-right from the *live* colour registers as the beam advances, so mid-line
  `COLBK`/`COLPF` writes recolour only the pixels drawn after them (rainbow /
  split-screen kernels). **Players, missiles and collisions are evaluated per
  pixel** too (phase 3): mid-line `HPOS`/`GRAFP` rewrites multiplex a sprite, and
  collisions accumulate / `HITCLR` at the beam. **ANTIC DMA is spread across the
  display-fetch window** `[cycle 32, 104)` (phase 4) instead of front-loaded at
  the line start, and a **`STA WSYNC` releases the CPU at HSYNC (cycle 104)**, not
  the next line — both per MAME `antic.cpp` (`CYCLES_HSTART` / `CYCLES_HSYNC`).
- **CPU timing** — 6502 "Sally" cycle-accurate (§62).
- **Distance to full cycle-accuracy** — the DMA spread is an even split across
  the fetch window, not the exact per-character steal positions (a relaxation
  MAME shares).

## Tooling & drivability

- **Script / MCP** — `--script` + `--mcp`.
- **Native window** — headless only (extended tier).

## Peripherals & connectivity

- **Emulated now** — analog joystick (pots) + fire; keypad.
- **Period peripherals (emulatable)** — the 4-port expander, trak-ball
  controller, the (rare) keyboard/voice add-ons.
- **Internet-capable** — **No**: a games console with no serial/modem path; no
  period or practical modern net device.
