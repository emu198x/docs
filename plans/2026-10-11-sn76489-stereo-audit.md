# SN76489 stereo output audit

Engineering-frontier accuracy investigation for emu198x/emu198x#149. Establish
which parts of the report remain true before proposing a correction. This
investigation does not authorise a new serialized audio pipeline.

1. Inspect `crates/ti-sn76489/src/lib.rs` and its SMS consumer. Check the port
   mapping against the primary reference and unchanged Mesen2/MAME code.
2. Compile a standalone public-API probe against the current chip crate. Isolate
   each tone/noise channel; sweep all 256 panning bytes. Require a nonempty,
   nonzero all-enabled control, then compare each side with the corresponding
   enabled or muted control. Capture failures, exact source revision and hashes.
3. Check deferred draining across a panning change: previously generated samples
   must retain their original routing. Identify which state would have to survive
   snapshots, and every runtime that serializes this chip.
4. Retain evidence and update the existing issue with verified findings. Write
   a bounded design before implementation, and obtain agreement for any schema
   extension. Do not claim Game Gear host stereo from a chip-only test.

## Verified findings

The 1,024-row public-API sweep fails 768 masks: 512 left-output failures and
512 right-output failures. Every channel has a nonzero all-enabled control;
256 masks that enable both sides of the active channel pass. The probe exits
101 on the invariant failure. A write after audio generation also fails the
historical-routing check. No production files were changed.

`take_buffer_stereo` unconditionally duplicates the mono buffer. Its panning
register is never used during mixing. Both the field comment and issue #149's
old proposal incorrectly describe alternating L/R bits. The primary reference
`reference/by-topic/psg-sn76489/psg-sn76489-reference.md`, section “Sega Master
System / Game Gear”, gives the correct high-nibble left / low-nibble right
mapping. The unchanged Mesen2 `Core/SMS/SmsPsg.cpp:Run` and MAME
`src/devices/sound/sn76496.cpp:sound_stream_update` corroborate all eight bits.
The oracle here is routing, not an assertion about analogue amplitude or the
PSG's other timing behaviours.

The issue's old impact assessment is also stale. Game Gear has its own
`runtime-sega-game-gear` catalogue using `runtime-sega-master-system-class`.
The live machine routes port 06 writes to the PSG but its
`take_audio_buffer()` drains mono; the shared runtime emits `AudioPacket`
with `channels: 1`. Fixing only the chip's stereo accessor cannot deliver
stereo to the host.

## Correction boundary

Mixing already-buffered channel samples with the final panning byte would
reroute earlier audio after a later write. Routing belongs where audio is
accumulated, with separate output/filter history, and must preserve writes
within a host sample. A follow-up design must test this timing explicitly,
including writes between the PSG's internal divide-by-16 clocks. Preserve the
mono API for mono consumers; add an explicit Game Gear stereo path through
the machine and shared runtime, including a two-channel host packet.

Adding serialized chip audio state would affect all current live-machine
snapshot consumers. Versions at the audited source revision:

| Runtime snapshot module | Version |
| --- | --- |
| `runtime-sega-master-system-class/src/snapshot.rs` (SMS and Game Gear) | 8 |
| `runtime-acorn-bbc-micro/src/snapshot.rs` | 8 |
| `runtime-coleco-colecovision/src/snapshot.rs` | 5 |
| `runtime-memotech-mtx/src/snapshot.rs` | 5 |
| `runtime-sega-sg-1000/src/snapshot.rs` | 5 |
| `runtime-sord-m5/src/snapshot.rs` | 5 |

Audit the chip's separate manual save/load API as well before choosing the
snapshot boundary. This is an investigation, not an approved pipeline/schema
design. Issue #149 remains open for the timed correction and end-to-end tests.

## Reproduction

Build `ti-sn76489` at the source commit in `provenance.json`, then compile
`probe.rs` with Rust 2024 using that build's `libti_sn76489-*.rlib` and dependency
directory. Run the executable directly and require its failure status as well
as the printed counts. The retained baseline reports:

```text
mask cases=1024, mismatches=768, left=512, right=512
pre-write samples retain left-only routing: false
```

All source, baseline output and hashes are retained beside this plan.

## Executed host-output probe

`host-probe.rs` loads a 32 KiB synthetic Game Gear cartridge through
`runtime-sega-game-gear::with_cartridge`. The guest writes port 06 and the PSG
ports, enables tone 0, and halts. All three runs assert HALT at PC 17, proving
the guest completed its writes. A real `AudioSink` captures runtime packets
while the machine runs to time 150,000.

Both-enabled (FF), muted (00) and left-only (10) runs each reach the host through
three one-channel packets. Both-enabled produces 2,402 finite, nonzero samples;
muted and left-only samples are exactly identical to it. The probe exits 101
when requiring Game Gear's host packets to have two channels. The captured
output therefore confirms the source trace end to end. Compile this standalone
probe against `runtime-sega-game-gear` and `emu198x-shell` built at the recorded
source revision, as with the chip probe.
