# Verify SN76489 tone countdown timing

Engineering-frontier accuracy work following source issue #267's PSG cadence
requirement. MTX supplies one PSG clock per 4 MHz CPU T-state. The shared chip
checks for zero before decrementing, which appears to add one internal clock
to each tone half-period. Confirm that independently before production changes.

1. Check the original TI SN76489AN frequency equation and pinned executing
   XRoar tone generator. Keep its actual source unchanged. Qualify period zero
   separately: the current shared reference claims zero means one universally,
   but XRoar and MAME distinguish discrete TI from Sega-integrated behaviour.
2. Capture tone output edges through the public register-image API, all three
   channels and both existing variants. Sweep nonzero periods and normal/wrap
   counter boundaries. Compare interval lengths with the full reference.
3. If confirmed, use the existing counter to decrement and reload in one tick;
   retain the current serialized fields. Add regressions that fail against the
   old code and agree with an independent frequency/cycle oracle. Do not bundle
   noise-clock staging or zero-period semantics without their own qualification.
4. Run chip/consumer tests, Clippy and formatting. Preserve evidence and update
   #267 without claiming its separate CTC interrupt requirement is resolved.

No schema or architecture extension is proposed by this bounded tone-counter
investigation. The pending stereo pipeline remains separate.

## Confirmed result and correction

The original TI SN76489AN datasheet, PDF page 2, specifies that the counter's
zero transition both toggles the output and reloads the counter. Its frequency
equation is input clock / (32n). The downloaded PDF matches the held primary
sidecar's hash; the page was rendered and visually checked. The shared reference
example waited an extra count too; that example and the unsupported universal
zero-period claim were corrected in umbrella commit `c4a514a3`.

The unchanged XRoar core supplies 3,069 rows: all three channels and all 1,023
nonzero periods, with two observed consecutive edge intervals per row. Its real
filter is linked; the wrapper supplies only checked allocation helpers. It
exercises normal register writes with time advanced between them and excludes
the first transition from the steady-state interval comparison. Every row also
satisfies the datasheet equation.

The public-API probe repeats all rows for both existing variants by inspecting
the tone-output bits in the chip's register image. All 6,138 baseline rows differ
from the reference: half-periods are 16(n+1) input clocks rather than 16n. A fresh
build from the recorded main commit reproduces the baseline byte-for-byte.
The permanent regression fails all 6,138 cases before production edits.

The correction decrements the existing counter before checking zero, then
reloads/toggles on that same tick. No fields, operation stages, APIs, dependencies
or snapshot layouts change. All 6,138 corrected public-API rows and permanent
regression cases agree with the reference. The pre-existing Sega-zero test had
pinned 32 clocks for N=1; its expectation is corrected to the 16-clock cadence
modelled for Sega zero/one by MAME and Mesen2. It is explicitly not TI-zero proof.

Across the chip and all six current machine consumers, 189 tests pass and 18
existing external-ROM tests remain ignored. Targeted chip/MTX/SMS Clippy with
`-D warnings` and workspace formatting pass. Complete outputs and hashes are
retained beside this plan. CTC edge-to-IRQ timing in #267 remains unverified.

## Separate remaining zero/noise discrepancy

The additional full-XRoar `zero` run gives 16,384-clock intervals on all three
TI channels: a zero reload maps to 1,024. Our corrected core still gives 16
clocks in both variants. MAME independently maps discrete TI zero to 1,024,
while keeping Sega zero at the shortest interval; Mesen2 corroborates Sega's
shortest interval. The original datasheet does not settle zero directly.
This is a retained implementation discrepancy, not a new physical measurement.

Issue #211's earlier universal zero→one premise therefore needs requalification.
The scalar counter-boundary correction does not settle TI zero behaviour or the
noise phase/slaving model. Neither #211 nor #267 can be considered fully resolved
by these tone-interval tests.

## Reproduction

With XROAR pointing to the pinned checkout:

```sh
cc -std=c11 -O2 -Wall -Wextra -Werror -ffunction-sections \
  -I "$XROAR" -I "$XROAR/src" -I "$XROAR/portalib" \
  reference.c "$XROAR/src/filter.c" -Wl,-dead_strip -o reference
./reference > regenerated.csv
cmp reference.csv regenerated.csv
./reference zero > regenerated-zero.csv
cmp reference-zero.csv regenerated-zero.csv
```

The linker flag is for the recorded macOS/Apple Clang build and discards unused
serialization/part-registration entry points; it does not replace executed chip
or filter code. Build `ti-sn76489`, then compile `probe.rs` with Rust 2024,
`--extern ti_sn76489=<build>/libti_sn76489.rlib` and
`-L dependency=<build>/deps`. Its default output covers 6,138 ordinary rows;
`probe zero` emits six separately classified zero rows. Require exact row counts
and unique channel/period keys before comparing. No empty output is accepted.
