# Indexed MC6809 read/modify/write diagnostic

The 96,800 cases expose bus placement errors in every writing indexed RMW
operation at Emu198x `77dc18eb`. All 88,000 writes occur two cycles before the
unchanged XRoar core writes. Final registers, write addresses/data and total
cycle counts agree. TST has no writes but differs in 8,776 of 8,800 bus traces.
Only 24 complete rows match, from coincident addresses/data in TST cases.

The matrix contains eleven documented operations, all 220 currently accepted
indexed postbytes, five offset patterns, four register seeds and two PCs.
Each case resets a flat 64 KiB memory image to `(address * 73) ^ (address >> 8)
^ 0xa5`, truncated to a byte, then writes four program bytes with wrapping.
The reference executes its unchanged CPU implementation. Our probe drives and
reads the public CPU pins. Interrupts stay inactive. These traces do not cover
sideband signals, the next instruction's fetch pins or live peripherals, and
are not a new hardware measurement.

`traces.zip` contains `cases.txt`, `reference.txt` and `before.txt`, each with
96,800 rows. `provenance.json` records their SHA-256 hashes, toolchains and
source identities. The current probe was rebuilt after formatting and both
outputs regenerated byte-for-byte before archiving. `summary.json` separates
bus, write timing, write effect, register and cycle-count mismatches.

## Reproduce

Extract the archive into a temporary copy of this directory. From that copy:

```sh
python3 generate_cases.py cases-regenerated.txt
cmp cases.txt cases-regenerated.txt
python3 -m unittest -v test_compare
python3 compare.py .
```

The nine comparator tests reject missing, empty, duplicate and malformed rows,
accept the full reference control, detect injected register/cycle/write errors,
and require the measured pre-fix mismatch counts. The known-fault test is a
check of the archived `before.txt`, not a requirement for future corrected
production code. Validation raises explicit errors even under Python `-O`.

Set `XROAR` to the pinned reference checkout, then compile and run:

```sh
cc -std=c11 -O2 -Wall -Wextra -Werror \
  -I "$XROAR" -I "$XROAR/src" -I "$XROAR/portalib" \
  reference.c "$XROAR/portalib/delegate.c" -o reference
./reference < cases.txt > reference-regenerated.txt
cmp reference.txt reference-regenerated.txt
```

Build `motorola-6809` at the recorded source commit with Cargo, then compile
`probe.rs` from that checkout so its Rust toolchain matches the library:

```sh
cargo build -p motorola-6809
rustc --edition=2024 -O /path/to/probe.rs \
  --extern motorola_6809=/path/to/target/debug/deps/libmotorola_6809-HASH.rlib \
  -L dependency=/path/to/target/debug/deps -o /path/to/probe
/path/to/probe < /path/to/cases.txt > /path/to/before-regenerated.txt
cmp /path/to/before.txt /path/to/before-regenerated.txt
```

Use the actual library path produced by that build. Do not overwrite the
archived pre-fix traces when testing a corrected core; compare its output via
`compare(inputs_path, reference_path, corrected_path)` instead.
