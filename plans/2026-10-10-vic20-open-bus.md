## Measurement result

The full guest completes on PAL and NTSC with a passing stability guard.
All 512 raster-register bytes agree with both matching physical dumps.
All 512 open-bus bytes disagree with each dump: Emu198x returns `$FF`
throughout. The NTSC header differs only in the guest revision identifier
(R01N versus the captures' R01C). No comparison bytes are excluded.

Native VICE xvic 3.10 is also wrong in this measurement. Its `$9100` samples
are all `$91`, and its `$9200` samples all `$FF`:

| Hardware dump | Native `$9100` differences / 256 | Native `$9200` differences / 256 |
|---|---:|---:|
| PAL 6561E | 162 | 256 |
| PAL 6561-101 | 255 | 256 |
| NTSC unspecified 6560 | 255 | 256 |
| NTSC 6560-101 | 171 | 256 |

The raw hardware pairs themselves differ at 93 PAL or 84 NTSC positions per
open-bus column: `$91`/`$92` versus `$20`. Do not select one physical dump
as a universal oracle or infer a chip-revision switch without tracing the
board and capture differences. Original provenance and identities are in
`198x/reference/by-system/commodore-vic20/2026-open-bus-measurement-observations.md`.

## Root-cause boundary and next work

`Vic20::mem_read` explicitly returns `$FF` for these addresses. Neither the
machine nor VIC-I stores the CPU/video bus history needed to return fetch
data. `Vic::render_cycle` reads screen and character memory for pixels and
skips rendering outside the framebuffer. Those calls cannot serve as bus
transactions: they repeat within a cell and do not cover the complete raster.

VICE provides useful precedent for distinct CPU and video bus values and an
alternating matrix/character fetch state machine (`vic-cycle.c`). Its I/O
decode does not reproduce these hardware readings: `$9100` falls through to
the retained CPU byte; `$9200` is in the VIA I/O handler's range but has
neither A4 nor A5 asserted, so `via1_via2_read` returns `$FF`. Copying either
path would leave most hardware samples wrong.

The next step is to trace board bus buffering and the VIC-I fetch sequence,
including idle cycles, using the original guest and primary wiring evidence.
A complete fix needs timed fetch state and retained bus values, not a
constant-address heuristic or calls attached to pixel painting. The exact
stage design and snapshot schema remain undecided and unapproved; no
production prototype is retained.

## Verification and retained evidence

The diagnostic is `survey_timing_measurements` in the existing VIC-I survey
test. It pins guests and all four physical dumps, requires the guest's done
flag and stable-raster result, asserts all raster-register control bytes and
records all five sections' mismatch coordinates and values. A successful
diagnostic means the measurement completed, not that open-bus accuracy passes.

Both native captures reproduce byte-for-byte in a second run. Deliberately
changing the first emulated `$9003` sample makes the control assertion fail
with exit 101; restoring the diagnostic passes. The normal survey helper
tests, targeted Clippy, formatting, fixture guards, ignore-reason check and
documentation links are the source checks for this measurement-only change.
The evidence folder includes original failed native-monitor setup output:
it used checkpoint 2 after deletion had made VICE reuse checkpoint 1. That
run reached its limit without a capture and is not counted as evidence.
