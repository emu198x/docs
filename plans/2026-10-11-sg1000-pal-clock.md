# SG-1000 PAL clock correction investigation

Lane: engineering-frontier accuracy. Status: reproduced; implementation and
snapshot change not yet approved. Console-specific oscillator confirmation
is still required. No production code has changed.

## Confirmed fault

The runtime advertises 3,579,545 T-states/second for both regions. The PSG
ticks once per T-state but PAL audio resampling assumes 3,546,893 Hz.
An original tone cartridge produces 48,441–48,443 samples per runtime second
on PAL. NTSC gives 48,000 in all three consecutive intervals. All six runs
execute audible guest code. [The retained probe](2026-10-11-sg1000-pal-clock-evidence/README.md)
exits nonzero on the three PAL intervals.

## Hardware evidence and limits

Sega's [SC-3000 service manual](https://segaretro.org/images/e/eb/SC-3000ServiceManual.pdf),
printed page 6 (PDF page 7), explicitly distinguishes NTSC 3.579545 MHz from
PAL 3.58 MHz. The PAL schematic on printed page 4 (PDF page 5) shows a
separate 3.58 MHz CPU/PSG oscillator and 10.738635 MHz VDP crystal. Both
pages were visually inspected; the retained PDF hash is in the evidence.
TI's TMS9918A/9928A/9929A data manual section 3.6 confirms the VDP crystal
and pixel divider, and restricts CPUCLK to TMS9918A.

This is manufacturer evidence for SC-3000. The [Gearsystem report](https://github.com/drhelius/Gearsystem/issues/99)
reports the same PAL console CPU frequency, without a retained waveform.
It is supporting community evidence, not a Sega console specification.
A Grandstand console schematic or physical oscillator observation remains
necessary before claiming that the SG-1000 nominal clock is settled.

MAME's `sc3000pal` configuration matches the Sega schematic. Its ordinary
`sg1000` driver is NTSC. Ares's SG family instead uses PAL colourburst times
4/5. Do not choose a value merely because one emulator uses it, or claim
that a full SC-3000 run validates the SG-1000's different input/RAM circuits.

## Approaches

1. Make the two existing PAL constants agree. This resolves the measured
   audio-rate mismatch but leaves the clock topology and raster relationship
   unverified, so it is insufficient for the accuracy objective.
2. Extend the existing per-machine phase accumulator and raster pacing
   (recommended once the console clock is confirmed). Keep the shared Z80
   half-cycle cadence, feed interrupt pins at both edges, schedule the VDP
   with its independent nominal frequency and tick PSG at the CPU rate.
3. Replace scheduling across the TMS family. This is wider than the evidence
   requires and would mix unrelated machines into this correction.

## Bounded design to approve

In `crates/machine-sega-sg-1000/src/lib.rs`, expose one authoritative regional
CPU frequency for the constructor and runtime profile. Replace the fixed
3/4 VDP accumulator ratio with the exact VDP-crystal/CPU-half-cycle ratio;
retain its remainder. Keep chip work in the existing cadence hooks per
`z80-machines-should-share-a-cadence-driver.md` and
`system-specific-run-loops.md`. No generic scheduler or dependency is needed.

Make `run_frame` finish on the VDP's actual next frame-count transition and
return T-states actually consumed. Audit every caller and debugger stepping
path; do not reset phase or assume every PAL frame consumes the same integer
number of CPU clocks. The runtime's `frame_ticks` remains an explicitly
nominal host budget if its contract requires one; emitted timestamps use
actual elapsed ticks.

Update `crates/runtime-sega-sg-1000/src/profiles.rs` and `runtime.rs` to use
that same clock and frame accounting. Preserve phase and frame state through
`crates/runtime-sega-sg-1000/src/snapshot.rs`; advance envelope v5 to v6 and
reject v5 before payload decoding because phase units/meaning change.
The exact field layout must be recorded before implementation.

## Verification tasks

1. Resolve nominal PAL console oscillator evidence and record it in the
   shared primary library. State any remaining oscillator phase/tolerance
   limits; do not invent a physical power-on phase.
2. Add integration regressions under machine/runtime `tests/`: runtime time
   versus audio duration, original tone frequency, actual raster wrap, mixed
   debugger/frame advancement, and long-run phase conservation. Require
   baseline failures with NTSC controls. Compare nominal-clock calculations
   to live reference configuration and guest observations, not copied code.
3. Check save/restore at multiple nonzero VDP phases, both regions, across
   frame boundaries; compare subsequent audio, pixels, CPU state and elapsed
   time. Verify v5 rejection and v6 continuation.
4. Run affected tests, all-target Clippy, formatting, source CI and inspect
   executed evidence. Keep controller #1735 separate. Merge only the tested
   tree; publish the complete probe and reference observations.

A separate discovery is that Sega's SG-1000 product page lists its hold
button, contradicting our console module comment. Check the real NMI/input
path in a separate bounded change rather than expanding this timing patch.
