# C64 multi-key connections and competing CIA outputs

Lane: engineering-frontier, failure-driven C64 accuracy. Extend the existing
keyboard matrix as approved after the reverse-scan correction.

The direct scans in `crates/machine-commodore-c64/src/keyboard.rs` cannot
follow an indirect path through several keys or connect two pins of the same
port. The board also treats all external lows as overriding output highs.
VICE 3.10 `src/c64/c64cia1.c` resolves connected groups and distinguishes
driven PB highs from input pull-ups: reverse ghost paths can be suppressed,
and an ordinary single PA low does not override an actively driven PB high.
Two connected PA low outputs can override that PB high.

1. Build a native guest in the adjacent evidence folder; use held-key events
   in Emu198x and immutable VICE snapshot inputs. Exercise three-key chains,
   same-port paths, input versus output highs, one versus two low outputs,
   both joystick ports, release controls, and PAL/NTSC. Record disagreements
   before changing Rust. Compare full bytes without joystick simulation;
   joystick cases compare the five connected pins because VICE's I/O simulator
   clears the upper three bits.
2. Add failing machine regressions, using the measured expected bytes. Extend
   the existing matrix with stateless connected-group resolution and the
   observed output-driver rules. Wire the resolved levels into CIA reads and
   preserve timer overrides, port directions and snapshot representation.
3. Verify all small two-by-two key configurations and larger paths with an
   independent reference harness, alongside native guests. Run existing
   machine/runtime/CIA tests, ROM boot checks, Clippy, formatting and the
   maintained joystick verification. Measure cost before considering caching.
4. Preserve source/tool identities, red/green evidence and claim boundaries;
   commit source and docs separately and merge after checks pass.

No new dependency, saved state or CPU/clock architecture is planned. SHIFT
LOCK's stronger mechanical contact is separate from ordinary Shift and is
not represented by the existing input API; this correction must not claim
coverage of that distinction or an analogue resistor-network simulation.

Primary sources: Commodore C64 Programmer's Reference Guide, p.94 and
pp.320–322; MOS 6526 datasheet, sheet 5/8 (actual pin reads, DDR, pull-ups and
PB6/PB7 timer outputs). VICE is implementation precedent, not original
hardware evidence. The frozen Older matrix was checked and has only direct
scanning; it supplies no reusable connected-group implementation.

## Results

The 36 native PAL/NTSC observations contained 20 disagreements before the
correction and zero afterwards. The before and after records contain exactly
identical reference rows. Input release controls and the distinction between
input pull-ups and actively driven highs remain visible in those records.

Three new machine regressions fail before the correction and pass afterwards.
The checked-in fixture covers 20,736 combinations: all 16 two-by-two key masks,
81 input/low/high configurations of four pins, and 16 joystick-mask pairs.
It was generated by compiling the relevant VICE 3.10 functions without edits;
`reference.py` extracts them from the local vendored source. Its wrapper sets
SHIFT LOCK false and supplies raw DDR-resolved drives with timers disabled.
All 36 native VICE results independently agree with that compiled harness
(after the documented five-bit mask for joystick-simulator cases).

The machine/runtime/CIA suite passes 293 tests, with 70 fixture/diagnostic
tests skipped by default. Both real-ROM boot tests were then explicitly run
and passed. Existing reverse-scan, timer-output, release and snapshot tests
still pass. Matching three-package Clippy with all targets and denied warnings,
workspace formatting, doc links and a native release build passed.

The maintained joystick sample at
`f67d4aeb6921d5fefa87b529f996c20bf39de211` passes 412 state/display checks,
48 native captures, all ten keyboard probes and four held-Fire mutations
rejected. Its historical final log message still mentions a known reverse
scan difference; the strict checker from the preceding reverse-scan plan
requires actual zero-mismatch rows and passes this record.

Timing is a small paired diagnostic, not a performance guarantee: three
alternating before/after pairs per scenario, each running 750 headless PAL
frames (150 before input, then 600 with keys released or Return/W/3 held).
The after/before median ratios are 0.954 with keys released and 0.993 with
the chord held. There is no measured slowdown in these runs, so no cache or
new derived state was introduced. Raw timings, binary hashes and scripts are
retained alongside the evidence; both executables can be run with `--script`
using these scripts. The first pair shows host-load variation, which is why
these short samples do not justify a speedup claim.

## Reproduction

From this docs repository (use a new output directory for each native run):

```sh
python3 plans/2026-10-10-c64-keyboard-ghosting/reference.py --vice-source ../../emulators/c64/vice-3.10 --output /path/to/reference-output
python3 plans/2026-10-10-c64-keyboard-ghosting/verify.py --samples ../../Code198x/code-samples --emulator ../emu198x/target/release/emu198x-c64 --output /path/to/native-output
```

`--record-baseline` permits and requires native disagreements when measuring
the old executable; the normal invocation fails on any mismatch. The baseline
verifier source is retained compressed because a later Ruff-only edit changed
its source hash. Native fixtures patch only a new VICE KEYBOARD snapshot copy;
loaded originals are never overwritten.

From the source repository:

```sh
cargo test -p machine-commodore-c64 --lib keyboard_
cargo test -p machine-commodore-c64 -p runtime-commodore-c64 -p mos-cia-6526
cargo test -p machine-commodore-c64 --lib boots_kernal_to_ready_prompt -- --ignored
cargo test -p runtime-commodore-c64 --test boot_invariants real_kernal_reaches_ready_prompt -- --ignored
cargo clippy -p machine-commodore-c64 -p runtime-commodore-c64 -p mos-cia-6526 --all-targets -- -D warnings
cargo fmt --all --check
cargo build --release -p emu198x-c64
```

## Claim boundary

This closes the observed ordinary-key network and output-contention faults.
It does not add a SHIFT LOCK input or distinguish its stronger contact from
ordinary Shift; that would require separately represented input state. It
does not establish full analogue electrical accuracy, every timer-driven
multi-key combination, or original-hardware parity. The existing light-pen
wiring follows VICE's separate direct-contact helper and is unchanged here.
The local ignored C64 knowledge page was updated; this tracked plan preserves
the same limits.
