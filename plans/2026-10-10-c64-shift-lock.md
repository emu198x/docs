# C64 SHIFT LOCK contact

Lane: engineering-frontier, failure-driven C64 accuracy.

Before this correction the runtime ignored `SHIFTLOCK`, and the matrix
stored ordinary left Shift only. VICE 3.10 `src/c64/c64cia1.c` distinguishes the mechanical lock:
when PA1 is actively driven low, that contact can defeat a driven PB high
without a second PA low output. A joystick pulling PA1 low does not satisfy
that output-driver condition.

## Investigation and proposed correction

1. Compile the unchanged VICE matrix/read functions with a wrapper supplying
   its separate SHIFT LOCK flag. Run a native Emu198x guest through the real
   input path, contrasting ordinary left Shift and SHIFT LOCK, forward and
   reverse scans, input pull-ups and output highs, additional contacts and
   release controls on PAL and NTSC. Retain source hashes and observations.
   VICE's KEYBOARD 1.1 snapshot omits its SHIFT LOCK flag; patching that module
   alone would not establish the reference's locked behaviour.
2. Add a separate boolean contact state to the
   existing `KeyboardMatrix` in `crates/machine-commodore-c64/src/keyboard.rs`.
   Overlay its PA1/PB7 connection while scanning, retaining the independent
   ordinary left-Shift contact. Extend the existing contention rule only when
   PA1 is an actual low CIA output. No analogue network or new pipeline.
3. Route `SHIFTLOCK` through existing `InputEvent::Key` handling and validation
   in `crates/runtime-commodore-c64/src/input.rs`. `pressed: true` means the
   lock contact is closed; `false` opens it. These are idempotent state events,
   as for other keys. Do not bind host Caps Lock or introduce toggle events.
   `release_all` clears both lock and ordinary contacts. Save the contact via
   existing serde derives; advance the C64 runtime envelope from 17 to 18 in
   `src/snapshot.rs`, explicitly rejecting older payloads before decode.
4. Add failing runtime/machine regressions before the correction, including
   independent release of the two parallel contacts, fresh-runtime snapshot
   restore and version rejection. Sweep the connected pins against compiled
   VICE; retain the ordinary-key fixture. Run machine/runtime/CIA tests, real
   ROM boot checks, formatting, Clippy and native probes. Commit source and
   evidence separately, then merge after CI passes.

The alternative of treating SHIFT LOCK as an alias for left Shift retains the
known electrical error and cannot preserve their independent release. A host
Caps Lock toggle would also require host event/focus semantics beyond this
bounded correction. The separate contact is recommended.

Primary prose: *COMPUTE!'s Mapping the Commodore 64*, discussion of
56320–56321, in `reference/by-system/commodore-c64/`. It places SHIFT LOCK in
parallel with left Shift. The differing output contention is VICE
implementation precedent; this work does not claim original-hardware or full
analogue validation. The frozen Older keyboard has no SHIFT LOCK state to
reuse. No new dependencies or CPU/clock changes are proposed.

Status: the user approved the separate contact and version-18 schema change
on 2026-10-10. Implementation and local validation are complete; source CI is pending.

## Baseline evidence

At source `6d55ce6ffa59754ba7279d689e8a1f8a6ad774a7`, the native guest
has 14 disagreements in 24 PAL/NTSC observations. All ordinary left-Shift,
released and source-free controls agree. With PA1 low and PB7 driven high,
ordinary Shift returns PB=$FF but the reference lock returns PB=$7F;
Emu198x returns $FF for both. Reverse lock scanning also loses PA1.

Both added runtime regressions fail before the correction: contention and
independent contact release each report `left: 255`, `right: 127`.
`baseline.json.gz` records every observation and source/tool identities;
`red.log.gz` preserves the failing test output. The VICE functions remain
byte-identical to the vendored source; only the harness supplies the separate
lock flag. These observations precede the production correction.

The prepared reference sweep covers 20,736 PA1/PA2/PB1/PB7 configurations:
lock open/closed, sixteen ordinary-key masks, 81 driver configurations and
eight valid joystick-mask combinations. Closing the lock changes 2,628 pairs.
The fixture is installed as `crates/machine-commodore-c64/test-data/vice-shift-lock.bin`
and consumed by the machine-level regression; `sweep-identity.json` records
its byte identity.

Reproduce the baseline and reference fixture from the docs repository:

```sh
python3 plans/2026-10-10-c64-shift-lock/verify.py --samples ../../Code198x/code-samples --vice-source ../../emulators/c64/vice-3.10 --emulator ../emu198x/target/release/emu198x-c64 --output /path/to/new-baseline --record-baseline
python3 plans/2026-10-10-c64-shift-lock/sweep.py --oracle /path/to/new-baseline/oracle/vice-matrix --output /path/to/new-sweep
```

Omit `--record-baseline` after the fix: every native comparison must agree.
Both commands require a fresh output directory. The original guest source
and generator from the adjacent ghosting plan are reused unchanged.

## Implementation and local verification

The contact is now a separate boolean inside the existing keyboard matrix.
Both scan directions overlay its PA1/PB7 connection without overwriting the
ordinary left-Shift bit. Only an actual low PA1 output enables its stronger
contention rule. The input accepts `SHIFTLOCK` case-insensitively and sets
state directly, so repeats cannot toggle the contact. No host Caps Lock
binding is added.

All five focused tests pass: the 20,736-case reference sweep, output
contention, independent release, idempotent input and fresh-runtime snapshot
restoration across every supported C64 model. The existing ordinary-key
20,736-case fixture remains green. The three-package machine/runtime/CIA
suite passes 298 tests; 70 external-fixture/diagnostic tests are skipped by
default. Both real-ROM boot checks were explicitly run and passed. Matching
all-target Clippy with warnings denied, workspace formatting, doc-link
self-tests and the release C64 build pass. Logs are preserved alongside this
plan. The initial suite exposed a remaining version-17 assertion in
`boot_invariants.rs`; it now pins the approved version 18.

Version 18 intentionally rejects older saves before decoding their payload.
The new state has no CPU/clock consequences. Accuracy claims are bounded to
the measured digital matrix and VICE's output-contention rules, with timer
outputs disabled in the new sweep; no physical-hardware or complete analogue
validation is claimed.

The native probe now has zero mismatches in the same 24 PAL/NTSC cases that
previously had 14. Every reference row, key set, driver setting and joystick
mask is identical between the before/after records. `fixed.json.gz` and
`native.log.gz` preserve the observations. The source commit and exact file
hashes are in `source-identity.json`.
