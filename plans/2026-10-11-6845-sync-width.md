# Preserve complete 6845 sync intervals

Lane: engineering-frontier accuracy. This is a bounded correction to the
existing character-clock counters; no fields, dependencies, API or snapshot
layout changes are proposed.

## Evidence and cause

At source `10892b445182cc5d8106cff7cd142f9a64d4cf10`, the
[retained public-pin probe](2026-10-11-6845-sync-evidence/README.md) fails 62 of
64 cases. `tick` starts HSYNC and then immediately increments its width counter.
`advance_vertical` does the same to VSYNC. A width of one disappears completely.
Its vertical-adjust and immediate-frame-restart returns also bypass the pulse
counter, so boundary coverage is required before claiming the correction.

Motorola 1977 PDF page 12 specifies horizontal character periods and 16-line
vertical sync. Hitachi 1987 U70-A printed page 148 / PDF 159 programs vertical
width 1–15 with zero encoding 16. MAME's unchanged `mc6845.cpp` schedules HSYNC
off after the full width; `handle_line_timer` advances an existing vertical
pulse before row/frame handling and before asserting a new one. MAME's H-zero
rule differs from the original Motorola source and is excluded from that
reference comparison.

## Work and verification

1. Compile the relevant unchanged MAME width stages in a small timing harness,
   retaining its source hash and exact extraction boundaries. Check all legal
   widths; distinguish this stage-level reference from a full machine boot.
2. In `crates/motorola-6845/src/lib.rs`, add public-port/public-pin tests for
   both variants, all widths, horizontal wrap, vertical raster heights and
   pulses crossing vertical adjustment/frame restart. Show the tests fail on
   the unchanged source. Replace the old private-helper width tests that encode
   the short-pulse error.
3. Advance already-active pulse counters before new-pulse assertions. Advance
   VSYNC before any vertical-adjust/restart early return. Preserve existing
   start positions, zero-H handling and all address/cursor behaviour.
4. Run the unchanged original 64-case probe, new counter-boundary regressions,
   and save/restore continuation checks. Run the chip, BBC, PET, CPC and CPC Gate
   Array tests plus affected Clippy checks. Inspect any changed consumer timing
   assertion against the reference rather than replacing a golden blindly.
5. Commit one passing source change; publish evidence and current chip status
   in docs. Inspect CI, merge exact reviewed heads, verify merged ancestry/tree,
   update private working/recovery notes, and remove completed clean worktrees.

R7 = 0, live width-register changes, half-line interlace, skew, register masks
and light-pen capture remain separate work. These tests must not be described
as proof of those behaviours.
