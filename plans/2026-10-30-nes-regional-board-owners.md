# NES NTSC and PAL board owners

Continue the approved #2144 programme in the engineering-frontier lane. Split the two implemented regional boards into fixed `machine-nintendo-nes-ntsc` and `machine-nintendo-nes-pal` owners over `common-nintendo-nes`. Keep the family runtime, existing profile IDs and aliases, cartridge/FDS paths, input peripherals and host APIs where practical. This does not establish a distinct Famicom motherboard implementation. No new registry dependencies or chip timing algorithms.

1. Verify pre-split saves before extraction. In `machine-nintendo-nes/src/lib.rs`, test CPU open-bus reads after both snapshot reconstruction and in-place restore; the hand-written snapshot omits `open_bus`. Add runtime tests in `tests/board_baseline.rs` comparing complete state, output, timestamps and audio sample bits for NTSC/PAL, with nontrivial cartridge video/audio and partial-field execution. Check held controls, Zapper/Four Score configuration, battery state and reset after restoration. Reproduce any defect first; fix fidelity before splitting, with explicit approval for any save-format change.
2. Freeze corrected original saves and continued output in `test-data/nes/board-split/`, with project-written ROMs and documented capture provenance. Corrupt a fixture to verify the comparison fails. List the old failure modes: wrong region accepted into a fixed owner, altered partial-frame continuation, stale cartridge/input/battery/firmware reset caches, changed DMA/mapper state, incorrect browser variant selection and mixed evidence ownership.
3. Move shared engine, input/region types and existing shared regression tests into `common-nintendo-nes`. Give each owner a fixed constructor and checked snapshot restore, with no board-selecting argument or machine-to-machine dependency. Use the established closed family dispatch pattern over typed boards; preserve CPU/PPU/APU/mapper algorithms. Add exclusive direct tests per owner for guest boot/rendering/audio, controller ports, mirroring, native boundaries, reset and state continuation.
4. Adapt the NES runtime, input/query/debug paths and callers. Validate snapshot region before changing live state; preserve the agreed save format and established media/firmware policy. Add separate registry/evidence roots and regenerate status. Run core/runtime/runner/fleet tests, targeted real local ROM checks where available, strict Clippy/rustdoc, formatting and all existing status/fixture/ignore guards.
5. Update current docs, site board routes/player identity and #2144. Verify site tests/build/accessibility and deployed routes. Merge only green checks, retain original PR commits on verified remote refs, inspect tracked/untracked/ignored contents, then remove all task worktrees, experiments, build caches and processes. Preserve unrelated primary checkouts and the active Atari 5200/PET worktrees.

Sources: `reference/by-system/nintendo-nes/nintendo-nes-reference.md` identifies RP2A03/RP2C02 and PAL RP2A07/RP2C07; `knowledge/decisions/nes-clock-topology.md` binds the implemented dot-clock ratios. Consult the vendored Mesen/Ares before any accuracy change. The three historical donor roots named by RULES.md are absent. The current Mega Drive and Timex splits are the structural precedent. SG-1000 is deferred here because its PAL clock evidence and SG-1000 II board identities require separate resolution.

The complete regression patch is retained in the issue comments. No save-schema change is made while v3/reject-v2 approval is pending. These samples do not prove arbitrary-phase save fidelity.

The v3/reject-v2 policy is approved. Add the CPU open-bus byte to `NesSnapshot`, both reconstruction paths and the snapshot capture. Reject versions other than 3 before decoding the payload. Retain the original v2 captures as negative restore fixtures and compare their frame packets against corrected v3 execution; separately freeze complete corrected v3 states and continuation before extraction. Preserve the existing chip after-restore hooks and all CPU/PPU/APU timing. The approval supersedes this plan's earlier pending-policy note and the legacy-read expectation in `save-state-format.md` for NES v2 only, because that format omitted unrecoverable machine state.
