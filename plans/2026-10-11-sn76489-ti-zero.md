# SN76489 discrete-TI zero-period correction

## Scope and cause

Engineering-frontier accuracy work, continuing issue #211. The ordinary
counter correction in source PR #1721 is the baseline. The existing universal
`max(1)` reload still makes a zero period produce 16-clock half-periods on the
discrete-TI profile. Unchanged full XRoar yields 16,384 on all three channels;
MAME independently maps discrete-TI zero to 1,024 internal counts and keeps
Sega zero at its shortest interval. The TI frequency datasheet does not specify
zero, so this is reference-implementation evidence, not physical measurement.

## Bounded design

Keep the existing variant selection, registers, counters and serialised layout.
At tone-counter reload only, use 1,024 for zero on `NoiseLfsr::Tms15` and one on
`Sega16`. Preserve the programmed zero in the ten-bit register. The current
public enum explicitly maps those selections to discrete TI and Sega-integrated
machines; this change does not introduce a new chip profile or claim that all
possible chips with a 15-bit LFSR behave identically. Ordinary nonzero periods
and in-flight counters retain their existing behaviour.

This is a small, specified correction within the approved accuracy programme,
with no new API, dependency, state field, architecture or snapshot version.
Noise mode 3 still needs its own edge/slaving correction and remains tracked by
#211. Do not extend the separately pending stereo proposal here.

   Require 60 distinct rows and retain source revision/hashes. Keep reference

2. Add `crates/ti-sn76489/tests/data/ti-zero-transitions.csv`, its provenance in
   the adjacent README, and a chip regression in `src/lib.rs`. Compare the
   observed first transition and both settled intervals in each direction.
   Run the regression on baseline and require failure before editing reload.
3. Change only the tone reload and directly relevant variant documentation in
   `crates/ti-sn76489/src/lib.rs`. Keep the existing Sega zero and exhaustive
   nonzero controls. Add full serde continuation coverage through the existing
   MTX snapshot test infrastructure in
   `crates/machine-memotech-mtx/src/lib.rs`, without new dependencies.
4. Run chip and affected machine tests, targeted Clippy and workspace format.
   Record exact results, public-probe zero results, and limits. Commit source
   and evidence separately, open a source PR, and merge only after exact-head
   CI passes. Keep issue #211 open for noise slaving.

## Reproduced result

The full reference emits exactly 60 rows. Before the correction, all 60 chip
cases fail: the first row observes `[80, 16, 16, 16, 80, 80]` where the reference
requires `[80, 16384, 16384, 16384, 80, 80]`. This distinguishes the retained
in-flight count from the wrong subsequent reloads, in both write directions.
After the correction all 60 rows pass, alongside the existing 6,138 nonzero
cases and Sega zero controls.

The full MTX serde continuation regression snapshots at six elapsed-clock
checkpoints (16, 17, 31, 257, 16,384 and 16,400), advances original and restored
machines by a further 70,000 input clocks, and compares nonempty, nonzero audio
and the complete continued serialised machine state. This exercises the
counter's 1,024 value, partial divider/sample phases and filter history through
the existing schema. It does not promote the legacy 30-byte register image to
a full snapshot.

The reference wrapper synchronises on observed tone edges before each case.
Writes occur at internal-clock boundaries with enough spacing for XRoar's
READY gate; these results do not qualify physical sub-clock write latency or
power-on phase. The reference generator and filter are compiled unchanged,
with allocator helpers only. No noise logic is changed by this correction.

## Validation and reproduction

Source commit: `ffe6b0bec301e956b5fd85dd25ba0cdbf3852900`.
The chip and all six consumers pass **193 tests**; **18 existing tests requiring
external ROMs remain ignored**. Targeted chip/MTX Clippy (`-D warnings`) and
workspace formatting pass. The standalone public-API probe reports 16,384-clock
intervals on all three TI channels and 16-clock intervals on all three Sega
channels. Full logs, wrappers, reference rows and hashes are in the adjacent
[evidence directory](2026-10-11-sn76489-ti-zero/).

Reference sources:

- [XRoar generator](https://www.6809.org.uk/git/xroar.git):
  `update_reg` and `sn76489_get_audio`; exact local revision and hashes in the
  provenance file. The command below links the real filter implementation.
- [MAME generator](https://github.com/mamedev/mame/blob/9391e1eff80eb04abd58d48218a1d3b9643c1ea8/src/devices/sound/sn76496.cpp):
  `write` explicitly distinguishes the Sega profile from zero→0x400. This
  source was inspected independently; MAME was not executed in this audit.

From the evidence directory with `XROAR` naming the unchanged reference checkout:

```sh
cc -std=c11 -O2 -Wall -Wextra -Werror -ffunction-sections \
  -I "$XROAR" -I "$XROAR/src" -I "$XROAR/portalib" \
  reference.c "$XROAR/src/filter.c" -Wl,-dead_strip -o reference
./reference > regenerated.csv
cmp reference.csv regenerated.csv
```

The linker option is for the recorded macOS toolchain. The wrapper asserts a
60-row run, register values, expected edge counts and successful output. The
Rust regression independently requires each row key in order and no trailing
rows. Build `ti-sn76489`, compile `probe.rs` with Rust 2024,
`--extern ti_sn76489=<build>/libti_sn76489.rlib` and
`-L dependency=<build>/deps`, and run `probe zero`. Require exactly six unique
variant/channel rows before comparing the recorded output.
