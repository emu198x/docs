# Preserve Spectrum-family video pipeline state before splitting Timex

Steve chose fixing save-state fidelity before the board split on 2026-10-30, superseding the Timex split plan's version-16 preservation requirement. #2209 reproduces eight changed pixels in the first resumed frame on both boards in modes 0 and 6; later frames/audio/time/final state agree. No machine extraction has begun.

The fix preserves the ULA engine's seven omitted mutable fields: pending bitmap, attribute and second-screen bitmap latches, border output latch, VidEN, M-cycle falling phase and previous falling address. Only the immutable config reference remains skipped and is reattached by each owner. No timing/rendering algorithms change. The chip engine and its six wrapper crates move to 0.2.0 because their positional serialized layouts change. The Spectrum runtime moves to version 17 and follows its existing version policy: reject v16 before decoding, since missing latch state cannot be reconstructed accurately. No new dependency packages are needed.

Exercise border and pending fetch phases, standard/Timex screen modes and each of the 13 family profiles; compare pixels, audio bits, clock and final state against uninterrupted execution. Use existing postcard and capture dependencies. Check explicit legacy v16 rejection atomically.

Keep config skipped. In the six wrapper repos bump their engine dependency and package to 0.2.0, documenting the save-format break. Run each repo's required format/Clippy/tests.

This work changes persisted state only. It does not claim the current timing, video colours, contention or ROM boot is independently accurate; #52 retains those hardware questions. The existing boot test passes its weak nonzero-screen-RAM condition and is not evidence of BASIC readiness.
