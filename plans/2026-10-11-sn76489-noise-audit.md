# SN76489 noise-clock audit

Engineering-frontier accuracy work, continuing source issue #211. The baseline
is `ffe6b0bec301e956b5fd85dd25ba0cdbf3852900`, including the two prepared tone
corrections. This audit changes no production pipeline or snapshot schema.

## Questions

1. Do fixed noise modes shift at input clock / 512, / 1024 and / 2048, as the
   TI SN76489AN datasheet page 3, Table 3, specifies?
2. Does TI mode 3 shift on actual tone-generator-3 output edges, including
   zero-period and mid-count register changes?
3. Which parts agree across references, and which phase/variant differences
   need further evidence before implementation?

## Bounded work

- Compile unchanged XRoar `src/sn76489.c` and its real `src/filter.c` behind
  the existing allocator-only harness. Record LFSR changes and tone edges,
  preserving generator code rather than copying a schedule into an oracle.
- Drive the public Emu198x register/tick API and inspect its existing partial
  register image for raw generator state. Do not claim host-audio equality.
- Cover periodic/white noise, all four clock modes, low/max/zero tone periods,
  settled rates and selected dynamic tone-period changes. Require nonempty
  traces with exact case counts, including controls that can distinguish
  rate-only agreement from correct edge slaving.
- Compare MAME and Mesen2 source behaviour independently. Do not assume their
  noise phase agrees with XRoar or claim an unexecuted core was run.
- Record the observations, primary-source limits and a concrete correction
  design if additional state proves necessary. Ask for the required schema
  agreement before implementing such a change; existing pending stereo and
  MC6809 approvals remain separate.

## Bounded TI mode-3 correction design

The settled trace confirms a distinct fault that needs no added state: connect
TI mode 3 to the rising edge of the already saved `tone_output[2]`. Capture its
previous value locally within the existing tick, tick tone counters, then shift
noise only on the observed low→high transition. While mode 3 is selected, leave
the independent noise counter untouched, matching XRoar. Keep Sega's current
path until its phase differences across references are qualified.

Before implementation, extend the full reference harness with 240 dynamic
cases: periodic/white, starting periods 5/15, every internal phase of the full
tone cycle, and target periods 0/1/7. Record eight shifts per case (1,920 rows),
including timing and shift-register state. Add the fixture and regression to
`crates/ti-sn76489/tests/data/` and `src/lib.rs`; require a baseline failure,
then verify the existing tone/zero tests, all consumers and snapshot continuation.
Add a slaved-noise configuration to the existing MTX full-snapshot continuation
regression in `crates/machine-memotech-mtx/src/lib.rs`.

The fixed noise clocks still need a retained clock level to model half-cycles
and mode changes; no such new serialized field is introduced by this bounded
correction. #211 stays open for that work and the Sega phase qualification.

## Findings and correction

The fixed modes run at the wrong rate on both current profiles:

| Mode | Current shift interval (input clocks) | TI Table 3 / XRoar interval |
| --- | ---: | ---: |
| 0 | 272 | 512 |
| 1 | 528 | 1,024 |
| 2 | 1,040 | 2,048 |

The existing code shifts at every countdown expiry, missing the alternating
clock level, and checks zero before decrementing, adding an extra internal
clock. This bounded correction leaves those fixed modes unchanged and keeps
that confirmed fault open.

For TI mode 3, the baseline period-1 control has the right 32-clock rate, but
all 128 recorded shifts occur without a simultaneous rising tone edge. A
rate-only comparison would falsely pass it. Across six periods (0, 1, 2, 7,
31 and 1,023), both noise types and 64 observed intervals, all **768** baseline
slaved observations fail timing or edge agreement. The corrected trace matches
all 768 reference intervals, LFSR values and edge observations. All other
**1,536** recorded observations (fixed TI and every Sega row) are unchanged.

All **1,920** dynamic observations across the 240 planned cases fail on the
baseline; all pass with the correction. The full reference generator runs
unchanged, including its READY checks. The wrapper writes through its normal
register interface and only synchronises traces on an observed LFSR change;
it does not set the internal counters or output phase.

The correction connects TI mode 3 directly to the existing tone output's rising
edge and holds the independent noise counter while that source is selected.
It uses existing serialized tone/output fields and introduces no schema change.
The MTX continuation test now covers 12 configurations (six phase checkpoints,
with and without slaved white noise), comparing nonzero audio and complete
continued machine state after a further 70,000 input clocks.

**Validation:** 194 tests pass across the chip and all six consumers, with 18
existing external-ROM tests ignored. Chip/MTX Clippy with `-D warnings` and
workspace formatting pass. The correction was tested as
`8286daeb61ec8a5930e905299003cf13f944933b`, then rebased without conflicts to
`dcb942931f97de6c9061dd76dd5ba763a053a1ef`. Whole-tree object identity proves
that rebase changed no files. The same check applies to the preceding TI-zero
correction: `ffe6b0be` → `cd0f37f1`, now based on merged tone fix `448992c2`.

## Sources and limits

- TI SN76489AN datasheet, PDF page 3, Table 3, inspected on the rendered page:
  fixed shift rates and the selected tone-generator-3 output. The bit-label
  column repeats a 00 row; it is not used as a selector-bit oracle. The table
  does not settle edge polarity or phase across mode changes.
- XRoar at `b8491ab945d3e83fc1e98d62359813cf8a537d1d`,
  `src/sn76489.c::sn76489_get_audio`: executed here. TI mode 3 uses actual
  rising tone edges; the independent noise counter is held while selected.
- MAME at `9391e1eff80eb04abd58d48218a1d3b9643c1ea8`,
  `src/devices/sound/sn76496.cpp`: inspected, not executed. Its noise countdown
  runs independently with full-cycle periods. This agrees on settled rate,
  but does not supply XRoar's edge-slaving guarantee.
- Mesen2 at `fabc9a62174f8734a113df6d244f5539ef6b8fcf`,
  `Core/SMS/SmsPsg.cpp::RunNoise`: inspected, not executed. Its Sega path has
  its own timer and alternating LFSR-input bit. Mode 3 loads the tone period;
  this is not the same phase model as XRoar's TI path.

The Sega expected-rate entries in `summary.json` are source-derived comparisons,
not a compiled Sega oracle. No physical edge measurement, startup qualification,
sub-clock write-latency claim or host-audio comparison against XRoar is made.
The public probe uses the existing register image only to observe generator
state; complete snapshot continuation is tested through serde separately.

## Remaining work and reproduction

The fixed generator needs a retained clock level to represent both half-cycles
and source switching accurately. That shared serialized stage would require
agreement and coordinated snapshot versions across all six consumers. Do not
encode the missing phase in unrelated output/counter fields to avoid that
requirement. Sega mode-3 phase must be qualified independently before changing
its source connection. These remain open under issue #211.

The [evidence directory](2026-10-11-sn76489-noise-audit/) contains wrappers,
traces, the failing regression log, passing checks, hashes and rebase identity.
Compile `reference.c` or `dynamic-reference.c` exactly as in the preceding
[TI-zero plan](2026-10-11-sn76489-ti-zero.md), linking unchanged XRoar
`src/filter.c`; each wrapper asserts its exact expected row count. Regenerate
both CSVs and compare them byte-for-byte before trusting the fixture.

Build `ti-sn76489`, compile `probe.rs` with Rust 2024 and the resulting rlib plus
its dependency directory, and capture stdout. Run `python3 compare.py` beside
the recorded baseline and corrected captures. It rejects missing/duplicate
keys, requires 768 corrected observations, checks the 128 rate-only controls,
and verifies that the other 1,536 observations are unchanged.
