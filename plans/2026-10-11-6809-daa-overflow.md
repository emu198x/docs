# MC6809 DAA overflow correction

Engineering-frontier accuracy work. Resolve the DAA V discrepancy retained in
PR #1717's full register diagnostic. Our `daa` function leaves V unchanged;
published hardware observations and XRoar agree that V becomes the new C XOR
the adjusted accumulator's bit 7. This is a small correction within existing
arithmetic and instruction stages, requiring no new state or snapshot version.

Primary observation:
`198x/reference/by-topic/cpu-6809/2026-daa-overflow-observations.md`, citing
[David Banks's original-device record](https://github.com/hoglet67/6809Decoder/wiki/Undocumented-6809-Behaviours#undefined-values-of-the-overflow-flag).
The full XRoar CPU, revision `b8491ab945d3e83fc1e98d62359813cf8a537d1d`,
produces all 65,536 A/CC combinations. Every result satisfies the hardware rule;
the wrapper checks all other registers and the two bus reads.

## Steps

1. Preserve the full-core wrapper, binary results and hashes beside this plan.
   The fixture is 65,536 pairs of adjusted A and complete CC in A/CC order.
2. Add a public-pin regression in `crates/motorola-6809/src/lib.rs`, backed by
   `crates/motorola-6809/tests/data/daa-results.bin`. Execute all combinations
   at PCs 4000/FFFE/FFFF. Compare all CC bits, A and every unchanged register,
   both bus reads and next-fetch pins. Confirm the baseline fails.
3. Update V at the end of the existing `daa` function, after C is finalized.
   Remove the DAA V mask from `register_reads_match_full_reference_bus_traces`;
   its 3,072 qualified rows must now compare complete flags.
4. Verify CPU/Dragon tests, formatting and targeted Clippy. Re-run the complete
   register diagnostic: only the explicit TSTA/TSTB reference conflict may
   remain. Preserve before/after evidence. Do not change those instructions
   or the pending memory/snapshot design.
5. Commit and push the bounded correction, with a source PR based on #1717
   until its parent merges. Merge only after the exact head passes CI. Keep
   issue #130 open for the remaining opcode and timing work.

## Verified correction

The full public-pin regression fails before the correction in 98,304 of
196,608 runs. Its first mismatch is A=00, CC=01: decimal adjustment gives
A=60 and retains C=1, so V must become one even though the addition has no
new carry. The baseline returns CC=01; reference CC is 03.

The correction passes all runs. The existing DAA example test explicitly
asserted preservation of the unspecified flag; it now checks observed V
clearing/setting and retained carry. The separate register-read regression
compares complete DAA flags without a mask. Its full 3,264-row diagnostic has
no remaining register differences; only 192 TSTA/TSTB timing/trace differences
remain, as documented in the preceding plan.

93 CPU tests, 75 Dragon machine tests and two synthetic-firmware integration
tests pass; none ignored. Targeted Clippy with `-D warnings` and workspace
formatting pass. No serialized or public state changes.

To regenerate the reference fixture, set XROAR to the pinned checkout:

```sh
cc -std=c11 -O2 -Wall -Wextra -Werror \
  -I "$XROAR" -I "$XROAR/src" -I "$XROAR/portalib" \
  reference.c "$XROAR/portalib/delegate.c" -o reference
./reference > regenerated.bin
cmp daa-results.bin regenerated.bin
```

`reference.c` wraps the unchanged full CPU, supplies flat memory and stops at
its instruction post-hook. The binary stores output A then CC in input A/CC
order. The prior register diagnostic's `probe.rs` and `compare.py` reproduce
`register-after.txt`; its raw mismatch counters retain the TST conflict.
Hashes and source identities are in `provenance.json`.
