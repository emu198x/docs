changes no chip fields or save-state schemas without the required agreement.

## Confirmed state gap

The XRoar collision probe uses only public writes and ticks. History A selects
fixed mode 0 at tick 0; history B selects mode 1. At input tick 512 both write
mode 0, resetting the shift register. All eight registers, all four frequencies,
all four counters, all four output states, LFSR, selected register and noise
control flags match. The retained noise-clock levels differ: A is low, B high.

Both counters equal 16 and both shift registers equal 0x4000. At tick 768 A
shifts to 0x2000 while B stays at 0x4000. At tick 7,424 their audible noise
output bits differ (A=1, B=0). Neither the countdown nor the LFSR/output bit can
stand in for the missing clock level. Audio/filter history is outside this
digital-state comparison and is not a legitimate replacement for chip state.

## Complete ares comparison

The unchanged ares generator and serialization implementation at
`0ac4d8220c507f2554b048a67cb52a745b32e7ba` execute behind read-only subclass
accessors. A small umbrella-header adapter imports the actual nall arithmetic,
arrays, serializer and ares type aliases without pulling in host UI registration.
No PSG method, integer type or clock rule is copied or replaced. The normal
umbrella-header build pulled unused host-registration dependencies into the
standalone executable; the recorded adapter isolates that dependency only.
The successful reference build reports 181 warnings from existing headers;
this is not a warning-clean reference build or a production-code warning.

Across 1,152 Sega-profile observations, 896 current shift intervals disagree
with ares, while every successive LFSR value matches. This confirms the existing
feedback sequence independently of the wrong clock rate. All 768 ares mode-3
observations in this setup lack a simultaneous rising tone edge: ares maintains
its own timer/clock level, unlike the XRoar TI path.

There is also an unresolved **output-bit** difference: 234 observations differ
because ares presents the bit shifted out, while Mesen2 and our current core
present bit 0 after the shift. This proposal does not silently select a side.
Physical reset/phase evidence is needed before claiming either convention as
Sega hardware truth.

## Source qualification

[SMS Power's SN76489 notes](https://www.smspower.org/Development/SN76489)
describe an independent noise counter and alternating clock bit, with one shift
per rising transition. Their shift-out explanation matches ares's output
ordering. These developer notes do not supply a phase-resolved hardware capture
for this comparison.

[Blargg's September 2008 timing discussion](https://www.smspower.org/forums/11371-PSGTiming)
interprets the TI datasheet as selecting tone 3's square-wave output directly;
the post explicitly calls for practical tests. This supports keeping the TI
and Sega interpretations distinct; it is not a physical measurement resolving
the disagreement.

XRoar holds the independent TI noise clock during mode 3. openMSX's
`SN76489::generateChannels` explicitly labels its contrary free-running choice
an assumption. The proposed stage retains the already selected XRoar TI policy,
with this limit recorded. Mesen2 and ares independently retain a separate Sega
clock level. The primary TI datasheet supplies fixed rates; exact power-on phase
and physical sub-clock write latency remain unqualified.

## Proposed bounded correction — approval required

1. In `crates/ti-sn76489/src/lib.rs`, extend the existing noise stage with one
   serialized `noise_clock_high: bool`. Keep the existing counter, period and
   output fields; initialize the new level low, matching the references' phase
   convention. Retain the current constructor's counter initialization and
   qualify power-on phase separately.
2. On each existing internal /16 tick, decrement the independent noise counter
   before checking zero. At expiry, reload the selected half-period, toggle the
   retained level, and shift only on low→high transitions. Fixed modes retain
   half-periods 16/32/64. Sega mode 3 uses its existing independent tone-period
   reload, with zero mapping to one. No extra clocks run during writes.
3. Preserve the new clock level across noise-control writes; those reset the
   LFSR, not the phase. TI mode 3 keeps the already implemented direct tone-edge
   connection and holds the independent counter and level. Leave LFSR feedback
   and noise-output bit ordering unchanged pending their separate qualification.
4. Preserve full continuation through derived serde and the six runtime
   envelopes below. Keep the existing 30-byte manual register image unchanged;
   document it as partial diagnostic/register state, never the continuation
   format. Do not reconstruct the phase from output or hide it in counter bits.

wrappers, the dependency adapter, captures, source hashes, warning log and

for the recorded macOS compiler. The comparison requires all 1,152 reference
and 2,304 baseline rows, unique keys and the actual subsequent output divergence;
an empty or partial run cannot pass.
